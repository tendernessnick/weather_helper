# 历史数据保留与持久化方案研究

日期：2026-11-14。本文记录官方资料核对和方案取舍。**未购买额外数据库/计算资源，未迁移 SQLite 主库，未变更应用服务的存储配置。** 主会话已通过现有 PG 模式云存储中的私有桶加密中转，完整取回并验证数据库快照；这不是业务数据库迁移。

## 先保留现有数据

当前服务使用 SQLite：`sqlite:////data/weather.db`。本轮读取的云端配置中 `VolumesConf=[]`，没有已配置存储卷的证据。不能把容器仍在运行、目录名为 `/data` 或应用健康检查通过，当作重新部署后数据会保留的证明。

### 本账户已核实的资源

主会话使用 `tcb env detail` 回读到：当前 `nick-cloudbase` 环境已有 PostgreSQL 字段，实例标识为 `pgdb-jd83nl4t`，`TenantType=SHARED`。因此，本用户**不需要先假定要新建 PG 环境**，应优先评估现有共享实例的接入方式与实际费用。

PG 模式云存储此前桶列表为空，主会话已建立私有桶 `weather-helper-backups`，用于 AES 加密后的快照备份。私有桶存在不代表 SQLite 已迁入 PostgreSQL；存储备份文件、读写业务表和开放 PostgreSQL 协议是三项不同能力。目前也不能从 `SHARED` 或实例 ID 推断公网连接已开启、已有业务数据库账号，或托管实例可直接被现有 SQLAlchemy 连接。

保全顺序：

1. 保持旧实例运行，不更新服务、重启、扩缩容或保存可能触发实例替换的配置。
2. 通过控制台 Webshell 进入**当前正在提供服务的实例**。
3. 使用 SQLite Online Backup API 在另一文件中生成一致性快照，不直接复制正在写入的主数据库。
4. 对快照执行完整性检查，记录各表行数、主要时间范围、文件大小和 SHA256。
5. 下载快照至本机，再复核文件摘要、完整性与表数据；备份验证通过后，才能安排持久化或迁移。

主会话本轮已确认旧实例的 Webshell 可用，并在运行中的旧容器上生成快照。终端原生 **File → Download File** 虽有入口，但本次实际返回“max size is 10240 bytes”，拒绝导出大文件，**未能用这条路径取回完整快照**，不能把入口存在当作下载成功。

最终采用的路径是：在容器内将快照打包并用 AES-GCM 加密，经现有 PG 模式云存储的私有桶 `weather-helper-backups` 中转，在本机下载后解密。主会话已验证 AES-GCM、ZIP CRC、SQLite完整性、12张业务表的行数与时间范围，并将快照还原至另一数据库验证通过。快照未放入公开站点目录，也未当作Git源码提交；解密密钥与云端密文分开保管。具体备份文件、摘要及验收证据以本目录备份验收记录为准。

这是对**备份时点**数据的保全。原服务继续运行后新增的天气记录不自动属于这份快照；后续正式迁移仍需要确定最后快照或增量同步边界。

`tcb cloudrun download` 的职责是下载已部署**代码**，不是导出实例运行时的 `/data/weather.db`。即使已保存服务配置和 Git 历史，也不能代替数据库快照。

- [SQLite Online Backup API](https://www.sqlite.org/backup.html)：适用于正在使用中的数据库的一致性备份。

## 建议主线：将业务数据迁移到托管 PostgreSQL

长期推荐让容器保持无状态，将数据库放在独立的托管 PostgreSQL 中。这样发布镜像、替换实例和容器回收不再依赖原实例的文件。CloudBase 自身也建议将数据库、文件等持久性状态放到外部服务。

优先候选是当前环境**已有的 CloudBase PostgreSQL 共享实例**。具体接入仍需在备份验证完成后，核对连接地址、权限、网络路径、备份能力和持续活动费用。如果现有实例不能提供适合当前后端的连接方式，再比较外部托管 PostgreSQL，不预先新建环境或购买另一套数据库。

### CloudBase PostgreSQL 的限制

- 官方“环境创建后不能切换数据库类型”是通用限制；但本轮实际回读已经证明该环境含共享 PG，因此此前“可能需要新建 PG 环境”的泛化判断**不适用于本用户当前事实**。
- 共享实例支持个人项目，按实际活动窗口计量；独享实例按规格与运行时长计量。
- 当前官方套餐表中，个人版支持 PostgreSQL 和数据导入/导出，但没有平台数据回档；标准版提供7天、企业版14天、企业高级版30天。实际实例的可用备份和恢复入口以控制台为准。
- 仍应保留独立的逻辑备份，并进行恢复演练。PG 的 `pg_dump` 是长期留存和迁移工具，不能把“平台支持备份”理解为本项目已经配置、已验证可恢复。

### 当前共享 PG 与 FastAPI/SQLAlchemy 的接入路线

CloudBase 官方文档列出 PostgreSQL 协议和 PostgREST HTTP 两种服务端访问方式。对本项目，先尝试保留已有 ORM 的 PostgreSQL 协议路线；不能用“平台支持该入口”代替“该共享实例已提供、已连通”的实际验证。

| 路线 | 对本项目的意义 | 仍需核对，本文未执行变更 |
|---|---|---|
| PostgreSQL 协议，内网/VPC或平台连接池入口 | 最能保留现有 SQLAlchemy Session、复杂SQL、事务和批量导入 | 该共享实例真实host/port/database/account、连接池模式和连接上限；若地址仅内网可达，需匹配VPC/路由及当前套餐权限 |
| PostgreSQL 协议，官方提供的公网入口 | 若账户已有可用公网入口，可在不假设VPC已配置的前提下评估 | 控制台是否对本实例提供此能力、TLS证书要求、账号和允许访问来源；不能从实例ID猜公网域名或自行开放全部IP |
| PostgREST HTTPS / RPC | 跨语言访问PG，不要求把API网关当作TCP端口；可作为无法直连时的候选 | 后端需要从ORM仓储改造成HTTP/RPC适配层，保留事务、并发和唯一性语义；不是修改DATABASE_URL即可完成 |

**读取连接信息的前置清单**：在该共享实例的控制台查看官方给出的连接方式、host/port、数据库名、业务账号、证书和连接上限；只记录非敏感摘要，密码/API Key只进入密钥管理或受保护环境变量。接入规划中不猜测 `pgdb-jd83nl4t` 对应的 TCP 域名，也不把通用“云数据库 PostgreSQL”的公网开通文档直接套用到 CloudBase 共享实例。

如果确认有可用 PostgreSQL 协议入口，SQLAlchemy 可显式使用 `postgresql+psycopg` 驱动，以避免不同SQLAlchemy版本的默认驱动差异。连接信息应由真实控制台值构造，不把占位串写入线上环境；TLS及证书校验按官方连接要求配置。保留一个进程级小连接池，控制总连接上限，并验证断线重连、事务回滚和平台连接池兼容性。若只提供VPC内地址，则先核对个人版的实际VPC能力，不能直接发布一个必然连不到数据库的镜像。

如果只有 HTTPS 接口，官方数据网关形态为 `https://<envId>.api.tcloudbasegateway.com/v1/rdb/rest/<table>`，使用服务端身份访问表或RPC。CloudBase的服务端API Key不可传到浏览器；当前React前端仍调用FastAPI，由后端承担数据边界。HTTP数据API不是PostgreSQL DBAPI连接，不能把HTTPS URL直接交给 `create_engine()`；原本跨多条ORM语句的逻辑事务需在受控RPC或其他明确的事务边界内重建，不能假设几个独立HTTP请求共享同一个事务。

正式接入前可做范围受控的只读连通验证，如服务端 `SELECT current_database(), current_user, version()`；该验证只证明当前身份能连通，不能证明业务写入、备份恢复或性能已经达标。本研究没有执行SQL、建立业务表、开通公网地址、修改VPC、重置密码或创建账户。

官方依据：

- [CloudBase 连接数据库](https://docs.cloudbase.net/database/postgresql/connecting-to-postgresql)：说明协议、HTTP访问路径及账号网络要求，具体连接信息以控制台为准。
- [SQLAlchemy PostgreSQL/psycopg 方言](https://docs.sqlalchemy.org/en/20/dialects/postgresql.html#module-sqlalchemy.dialects.postgresql.psycopg)：现有ORM适配方向。
- [CloudBase 云托管网络问题](https://docs.cloudbase.net/run/faq/network)：内网地址可解析不代表路由已连通，VPC配置和版本发布需要分别验证。

### 费用估算：小数据库不等于低计算费

按2026-11-14核对到的官方页面：

| 计费项 | 官方口径 |
|---|---|
| PostgreSQL CPU | 342资源点/核·小时，按1000点=1元折算为0.342元/核·小时 |
| PostgreSQL 容量 | 0.5资源点/GB·小时，折算为0.0005元/GB·小时 |
| 共享实例活动计量 | 每5分钟一个窗口；有数据库活动的窗口按0.5核计量 |
| 套餐资源点 | 与同一环境内其他计费资源共享抵扣，不能重复计算为各资源独立免费额度 |

本项目调度器当前每5分钟执行一次 `push_check`，另外还会抓取天气并访问数据库；服务存在持续访问数据库的可能。因此不能按“只有约131MB数据、平时没用户”推断数据库几乎免费。

如果数据库在整月每个5分钟窗口都被访问，按30天粗算：

```text
0.5 核 × 24 小时 × 30 天 × 0.342 元/核·小时
= 123.12 元计算用量
```

这只是**抵扣套餐资源点之前的计算用量估算**，不是给该账户的实际账单。还未计入存储、网络、其他服务用量或实际抵扣；实际访问窗口、套餐资格和购买页价格都可能改变结果。当前环境已经有共享 PG，不能把以上数字当作必须新购实例的固定月费，也不能当作一定全部新增的费用；应先核对当前PG已有活动与资源点消耗，再比较接入Weather Helper后的增量。共享实例在约131MB规模时的存储部分相对很小，持续计算活动才是本项目需要重点评估的成本。

降低活跃窗口前应先评估提醒、采集频率和用户体验，不能单为省费静默降低天气更新或提醒可靠性。也应比较其他托管 PG 的固定价格、休眠规则和连接限制。

### 具体迁移工程任务（协议入口可用时的优先路线）

这是一份后续工程清单，本文未实施这些变更。不能只新增驱动并修改 `DATABASE_URL`。

1. **连接与边界**：核实该共享实例的协议入口；在隔离测试中配置显式 `psycopg` 驱动、小连接池、TLS和最小权限账号。为业务表规划独立schema或可辨识前缀，不触碰现有PG中的 `auth`、`storage` 等平台对象，也不将应用数据暴露为匿名可读。
2. **数据库适配**：拆分 `backend/app/db.py` 的 `PRAGMA table_info` 等SQLite专用迁移；使用SQLAlchemy方言/Inspector或明确迁移脚本支持两种后端。替换 `backend/app/api/admin.py` 的SQLite `strftime` SQL，并调整文件大小/路径等SQLite专用诊断展示。
3. **可重复数据导入**：从已验证的离线SQLite快照导入业务表，按表分批、明确事务和失败恢复位置；保留原有香港本地日期语义，校验主键、布尔值、JSON文本、唯一约束和索引。导入已有ID后修正PG自增序列，避免后续新记录冲突；导入过程不启动重复的天气采集调度器。
4. **并行验证**：在隔离测试库或测试schema验证完整接口/统计回归；对预测快照、测站真值、融合、BSS、评分和打卡/提醒执行对照，增加并发写入、回滚、断线和唯一冲突验证。检查大统计查询与迁移批次是否超出共享实例资源和请求限制。
5. **切换与增量**：确定最后快照/增量的时间边界与短时维护窗口，避免旧实例继续写SQLite、新实例写PG而造成数据分叉。切换前验证当前账号、已导入行数、关键时间范围和备份恢复；只在数据齐备后发布应用配置。
6. **持续运维**：为PG添加按计划的逻辑导出与恢复演练，私有备份桶只存放密文，解密密钥与密文分开保管。观察CPU、连接数、查询延迟及资源点增量；如果要减少5分钟活跃窗口，先验证对提醒、采集和数据新鲜度的影响。

迁移验收应逐表核对行数与关键时间范围，并抽样比较旧库和新库的评分、统计与逐小时结果。旧快照保留至新服务验证通过，回退方案需要同时考虑代码和数据，不只回退镜像。

## CFS：能够持久保存文件，但不直接作为 SQLite 的默认推荐

CloudBase 官方支持挂载腾讯云文件存储 CFS。CFS 的文件在容器销毁后仍可保留，但它使用 **NFS 网络文件系统**，不是容器本机持久块设备。

SQLite 依赖文件锁与同步写入语义。SQLite 官方指出网络文件系统的锁和 `fsync` 可靠性会因实现与部署而异，并明确说明 WAL 不适用于跨主机网络文件系统。故“CFS可挂载”和“SQLite可可靠作为长期在线库运行”是两件事；保持单实例只能限制应用副本数，不能据此免除文件系统语义核对和故障恢复验证。

本轮在旧实例读取到 `journal_mode=delete`，避免了当前数据库依赖 WAL 的问题，但不能据此直接证明未来 NFS 挂载下的可靠性。若评估 CFS，应先取得供应商对 SQLite 使用场景、锁、同步和故障恢复的明确支持结论，并验证部署切换期间没有两个实例同时写库。

CFS 配置还要求同地域 VPC 与子网。当前官网套餐表列出的云托管 VPC 连接能力从标准版起支持，个人版未列为支持。**这是官方套餐表限制，不是对该账户控制台实际资格的最终认定**；存量权益或控制台能力应单独核对，不能直接断言用户一定不能挂载，也不能在未确认费用的情况下升级套餐。

官方依据：

- [CloudBase 挂载 CFS](https://docs.cloudbase.net/run/deploy/configuring/storage/cfs)
- [当前云数据库环境套餐能力](https://cloud.tencent.com/document/product/876/140498)
- [SQLite 在网络中的使用注意事项](https://www.sqlite.org/useovernet.html)
- [SQLite 文件锁与损坏风险](https://www.sqlite.org/howtocorrupt.html)
- [SQLite WAL 限制](https://www.sqlite.org/wal.html)

## 可比较的替代路线

| 方案 | 适用性与代价 |
|---|---|
| 托管 PostgreSQL | 主推荐方向，数据库独立于应用生命周期；需要完成SQL/诊断/迁移适配并核对持续活动成本 |
| 轻量服务器或其他带持久本地盘的平台 + SQLite | 保留现有数据库结构，迁移代码较少；需要维护系统、容器挂载目录、备份和监控，重建服务器时也必须保留磁盘或还原备份 |
| 本地 SQLite + 定期上传私有对象存储快照 | 可作为过渡保护，必须用在线备份API、校验、版本留存与恢复流程；仍存在最近一次备份之后的数据丢失窗口，不等于持久在线数据库 |
| CFS/NFS上直接运行SQLite | 可保存文件，但需额外论证锁/同步语义、实际套餐资格和费用；不作本项目默认推荐 |

对象存储适合放**已生成的备份对象**，不能把普通对象存储挂载工具当作具有完整 SQLite 所需锁与同步语义的本地文件系统。代码仓库同样不应保存线上数据库、订阅密钥或导出的用户数据。
