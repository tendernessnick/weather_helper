# 独立复核记录

日期：2026-11-14。范围为本轮前后端工作树变更；复核不操作生产写入接口、不修改数据库、不操作部署控制台。这里只记录与本轮目标直接相关的问题，浏览器矩阵和最终构建结果由集成验收单独记录。

## 已落实的关键修复

- **薄样本校准导致 500**：原 `recalibrate` 在有干湿样本、但每个桶均不足 10 条时生成空插值结点，首次调用抛 `IndexError`，会影响球场天气及排行榜。现在回退原预报；有针对性回归。
- **统计集合和分母**：BSS 的模型误差和气候基线现在只比较两者都有值的同一批球场小时；Peirce 使用实际干/湿样本作为分母，缺任一类返回空值，恒报干且两类观测均存在时为 0。
- **过期、缺失和时间参数**：排行榜排除过期记录，中位数使用真正的中位数；非法、过去、非整点及超范围输入返回 422；带时区的输入按时刻转换为香港时间。
- **雷达下载不能冒充更新**：SWIRLS 使用官方发布时间而非本机下载时间；重复下载同一期资料不重复插入。后端代理另以真实 HKO CSV 只读核对列名、时间格式和四个步长，不依赖自制 fixture 推断兼容性。
- **场次结论有证据边界**：完整场次逐小时覆盖、3 小时预报期限、25 分钟雷达期限及离线状态参与判断；明确最高单小时风险不是整场降雨概率，融合值是尚未独立概率校准的启发式指数。
- **提醒不把未知写成无雨**：后端返回 `risk_status: unknown` 与空风险值；前端兼容旧响应的缺概率情形，使用“无法判断”提示。只有雷达报雨、没有数值概率时不再显示 `None%` 或 `—%`。
- **跨时区订阅**：输入明确标注香港时间，默认值和未来校验使用同一时区；无效时间先阻止提交。推送就绪及订阅有等待上限，失败后明确页面内提醒需要保持页面打开。
- **服务与部署**：保留开工前已有的启动/调度单任务互斥；静态文件解析限制在构建目录内，未知 API 不再返回成功的 HTML。保留 CloudBase 单实例常驻及数据库持久化边界，不把 GitHub 推送当作上线证明。

统计专项测试：`backend/tests/test_stats.py`，本代理执行时 27 项通过。后端完整测试及调度互斥专项由后端代理执行；最终结果以集成验收为准。

## 本轮独立复核提出的收口项

以下为审查时发现，已逐项发给集成代理；此节不是尚未修复的最终缺陷清单，集成时应记录处理结果。

1. **排行榜页面长时间停留后仍显示旧低风险排名（P2）**。`frontend/src/pages/Best.tsx` 审查时只在切换选择或手动重试时请求，未在恢复页面或数据过期后隐藏排名。建议按共享天气时钟验证 `data_status.fetched_at` 及选定时段，失效时提示刷新；不能只在服务端响应生成时判一次新鲜。
2. **雨图把空临近预报画成绿色无雨（P2）**。`frontend/src/components/RainMap.tsx` 审查时使用 `c.nowcast?.rain ? 红 : 绿`，但后端在雷达过期后正确返回 `nowcast: null`，因此整张雨图可能全绿，图例仍为“球场无雨”。建议空值/过期画灰并标为缺数据；整张雷达图过期后不提供实时雨团距离建议，优先展示实际香港时间而非始终声称“+30 分钟”。
3. **球场元数据请求缺超时（P2）**。`frontend/src/pages/CourtDetail.tsx` 审查时仍用独立 `fetch` 获取球场基本资料。如果天气和校准请求已结束、只有这个请求停滞，`Promise.all` 将持续等待，刷新按钮也保持不可用。建议纳入通用有超时 API 请求或提供统一取消期限。

## 验收重点与限度

- 三语、窄屏和键盘导航；收藏持久化及筛选组合。
- 预报缺失、部分覆盖、更新时间未知、过期、页面长开和离线后，不能继续给出绿色低风险结论。
- 快速切换排行榜时间时，旧响应不能覆盖新选择；由排行榜带入的场次时间不能因缺资料而悄悄换成另一场。
- 香港与 Phoenix 两种浏览器时区下，显示场次、订阅默认值与提交时间一致。
- 浏览器 API 均用确定性 fixture，不进行真实上报、打卡、订阅或反馈写入。
- 本轮不证明模型预报技巧提升、不证明生产持久卷配置，不代替生产部署后只读探针检查。


## 集成收口结果

上述三项均已处理：Best 用每30秒时钟校验来源和时段，后台恢复/每5分钟刷新；RainMap 缺失与过期场地画灰，图过期提示并停止雨团距离建议，步长改为实际香港时间；CourtDetail 元数据请求加入20秒超时与取消。对应 browser-smoke 覆盖过期排行榜、灰色缺数据雨图；生产构建和完整测试通过。
